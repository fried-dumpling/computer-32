# Hneemann Digital — 서브컴포넌트 I/O 녹화 & 재생(Replay) 테스트벤치 (구현 인계용)

목적: 전체 CPU 시뮬레이션에서 특정 서브컴포넌트(예: ROB, 디코더, 리네임 테이블)의 입출력을 사이클 단위로 녹화한 뒤, 그 서브컴포넌트만 단독으로 재실행해 원래 동작을 재현/검증한다. 주 용도는 **수정 전후 동작 동일성 확인(회귀 테스트)** 과 **문제 구간의 격리 디버깅**.

## 1. 녹화 (Capture)

1. 대상 서브컴포넌트의 모든 입력/출력에 Probe 부착, "Show in measurement graph" 활성화.
2. 리셋 직후부터 실행 (내부 상태를 리셋 상태로 맞추기 위함).
3. Measurement 값 테이블을 CSV로 내보내기 → 사이클별 입력/출력 기록 확보.

## 2. 재생 방식 — 두 가지 중 선택

### 방식 A (권장): Test 컴포넌트
- 변환 스크립트로 CSV → Digital 테스트 케이스 문법 생성 (입력 열, 출력 열, 클럭 `C`).
- 입력 인가 + 출력 비교 + 불일치 행 표시를 Digital이 자동 처리.
- `X`(don't care), `Z`(High-Z) 지원 → tri-state 신호, 비교 제외 사이클 처리 용이.
- 서브서킷 파일 안에 넣어두면 회귀 테스트로 계속 재사용 가능.
- **단순 동작 재현/검증 목적이면 이 방식 사용.**

### 방식 B: ROM 기반 재생 회로
서브컴포넌트를 다른 회로 안에서 실제로 구동해야 할 때 사용.
- 구성: `Counter(클럭 증가) → ROM 주소`, `ROM 데이터 → Splitter → 서브컴포넌트 입력`.
- CSV → hex 변환: 각 사이클의 입력 비트를 이어 붙여 ROM 워드 1개로.
- 출력 검증: 기대 출력 ROM(같은 주소 공유) + Comparator → 불일치 시 **Break 컴포넌트**로 정지 → 첫 divergence 사이클에서 멈춤.
- Digital 데이터 폭 최대 64bit → 넓은 입력은 주소 공유하는 ROM 여러 개로 분할.
- tri-state 입력은 enable 비트를 별도 녹화하고 ROM 출력 뒤에 Driver 컴포넌트로 Z 재현.
- ROM은 조합 읽기 → 카운터 엣지 직후 입력이 바뀜. 원본 입력이 레지스터 출력이었다면 타이밍 일치하지만 1사이클 어긋나기 쉬움 → 첫 몇 사이클을 원본 measurement graph와 대조해 정렬 확인.

## 3. 재현이 유효한 조건 (반드시 지켜야 함)

| 조건 | 위반 시 |
|---|---|
| 초기 내부 상태가 녹화 시작 시점과 동일 (리셋부터 녹화) | 첫 사이클부터 결과 불일치 |
| 완전 동기식 입력 (클럭당 1회 샘플로 충분) | 비동기 리셋/셋, 래치, 다중/gated clock 사용 시 사이클 내 변화 손실 |
| 서브컴포넌트 미수정 상태 | 아래 참고 |

**핵심 제약 — open-loop 재생:** 녹화된 입력에는 "원래 출력에 대한 나머지 회로의 반응"이 이미 반영되어 있다. 서브컴포넌트를 수정해 출력이 한 번이라도 달라지면, 실제 회로라면 입력도 달라졌어야 하지만 재생은 옛 입력을 그대로 넣는다.
- 수정 전후 동일성 검증(회귀 테스트)에는 완전히 유효.
- 수정 후에는 **처음 출력이 달라지는 사이클까지만** 의미 있음. 그 이후 결과는 신뢰 불가.
- 예: ROB를 단독 재생 중 stall 신호가 1사이클 늦게 나오면, 원래는 front-end가 dispatch를 멈췄어야 하지만 녹화 입력은 계속 dispatch를 넣음.

## 4. 구현 작업 목록

- [ ] CSV → Test 컴포넌트 문법 변환 스크립트 (방식 A)
- [ ] CSV → ROM hex 변환 스크립트 (방식 B, 필요 시) — 입력 비트 패킹 순서와 Splitter 순서 일치시킬 것
- [ ] 재생용 래퍼 서킷 템플릿 (Counter + ROM + Splitter + Comparator + Break)
- [ ] 녹화 대상 서브컴포넌트 우선순위 결정 (예: 디코더 → 리네임 → ROB 순)
