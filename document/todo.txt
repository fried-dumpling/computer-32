LD buff:
info: addr, data, Avalid, Dvalid, inst-id

when issue:
allocate buffer fot the dispatched inst.

loading addr (same struct as normal FU ld):
lda addr to corresponding buffer.
set Avalid flag to true

loading data:
lda data to corresponding buffer.
set Vvalid flag to true

%if buffer is Avalid:
send the valid lda out to port in id order (using store-buffer's queue)

% if buffer is Dvalid:
send the valid lda out to ROB in id order (using store-buffer's queue)

* each buffer holds:
- addr: 32bit
- data: 32bit
- Avalid: addr is ready
- Dvalid: data is ready
- inst-id & epoch (for comp)

ST buff:
info: addr, data, inst id, valid bit.

% valid bit means that it is a occupied space and has correct inst-id loaded
% which happens at a dispatch cycle

when issue:
allocate memory for the dispatched inst.
set the valid bit to one.

- notice:
dispatch only happens one at a time (for now at least)

when reciving data/addr
set selected set of register to data/addr
two loading of data/addr set can happen simultaneously

when committed:
outputs correlating set of datas and remove it from the buffer

1: load / store gets pushed to buff at the same time
